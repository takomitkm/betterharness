# 十九、E4 线：乐观确认（Optimistic Confirm）——行内写操作的交互范式

> 来源：2026-11-13 从 ZCode 侧「重命名会话」需求转写。原语境是「重命名对话框 + 侧栏列表」，
> 本仓库无此组件；其生态位对应我们的 **行内写操作**（Outbox 记录的重试/取回、附件移除、
> 候选接受等「一次写、等宿主确认」的交互）。内核已具备的 handoff/settle 台账语义即为
> 这套交互的底座——E4 把「消息提交」的可靠性语义推广到所有行内写操作。

## 19.1 交互契约（乐观确认）

**原则：UI 先走，结果后到；失败回滚，绝不二次打断。**

1. **确认即关闭**：用户按 Enter（或点确认）→ 对话框/编辑态**同步关闭**、焦点归还。
   这一步是纯 UI 动作，**不做任何 await**。
2. **在途态可见**：目标行进入「进行中」显示——标题/标签半透明（opacity 0.5）+ 灰化 +
   12–14px spinner。**不改变行高**（禁止布局跳动）。行仍可点、可 hover、可右键。
3. **在途态以身份为键存在轻量 store**（非组件内 state）：虚拟列表滚出屏幕再回来、
   窗口重开，状态仍在。键 = 行身份（会话/消息/资产 ID）。
4. **成功路径**：用宿主返回的 meta 更新行内容（标题、时间戳、未读等），清除在途标记。
   - 排序若按标题/最近活动：**行位置等成功之后再变**（不按下就跳位，避免手追行）。
   - 不重置选中态、不把列表滚回顶部。
5. **失败路径**：行内容回滚到**按下前的快照**（不是当前 store 值——期间可能被别的操作改过）；
   清除在途标记；弹 toast（沿用既有错误文案体系）；**对话框保持关闭**，不弹回。
   - 失败**不自动重试**（写操作自动重试易与旧请求打架）；用户想重试自己再点一次。
6. **取消路径不受影响**：取消/Esc 完全不走乐观逻辑。

## 19.2 竞态与幂等

| 场景 | 契约 |
| --- | --- |
| 连按 Enter | 第一次即关闭对话框，后续 Enter 落到别处 → 天然不重复提交 |
| 在途期间对同一目标再次发起写 | **以最后一次为准**；旧请求的迟到响应**不得覆盖**新值（自增请求序号/版本号校验） |
| 在途期间目标被删除/归档/切走 | 直接忽略响应：不报错、不复活行 |
| 在途期间其它操作（切会话、发消息、置顶、归档） | 全部照常，不受影响 |
| IPC/宿主一直不回 | **兜底超时 15s**：按失败处理（清在途标记 + toast），不许出现永久转圈 |

## 19.3 输入边界

- 值 trim 后与旧值相同 → 直接关框，**不发请求**（unchanged 分支）。
- trim 后为空 → 视为取消，保持旧值，**不发请求**（避免写空值进库）。
- **中文输入法**：Enter 在组词状态下只上屏、不确认（现有 IME 守卫保留——KD 契约不破）。

## 19.4 明确不做

- 不弹二次确认、不做模态遮罩、不阻塞输入框、不锁侧栏/列表滚动。
- 不在 IPC 期间禁用同行的「归档/置顶/删除」等操作。

## 19.5 与内核语义的映射（本仓库落地方式）

| 乐观确认概念 | 本仓库对应 |
| --- | --- |
| 对话框关闭（不等结果） | UI 层同步动作，无 await |
| 在途 store（按身份键） | 新增 `inflight: HashMap<Id, PendingWrite>`（Rust 侧台账 or TS 侧轻量 store；虚拟列表要求非组件 state） |
| 成功更新 meta | 宿主回执 → `settle` 同族语义 |
| 失败回滚到按下前快照 | `PendingWrite` 携带发起时的快照；失败恢复快照 |
| 迟到响应不覆盖 | 自增 `write_seq`（对齐 BM07 `persist_revision` CAS 思路） |
| 15s 兜底超时 | `Effect::ScheduleTimeout` 同族（D021 已有真触发实现） |
| 目标已删除则忽略响应 | `settle` 的「记录不存在 → 忽略」纪律（FM21 同族） |

## 19.6 验收（E4a 交付时必须的测试）

1. **0ms 关闭**：Enter 后同一帧内对话框/编辑态消失（渲染层断言，不等 IPC）。
2. **在途可见**：行显示 opacity 0.5 + spinner，行高不变（几何断言）。
3. **成功**：标题更新 + 在途标记清除 + 位置仅在成功后变化。
4. **失败回滚**：标题退回**按下前快照**（期间被别的操作改过也不受影响）+ toast + 对话框不弹回。
5. **迟到响应**：在途期间再次发起写，旧响应到达后标题仍为新值（序号校验）。
6. **目标消失**：在途期间删除目标，响应被忽略、无报错。
7. **超时**：15s 无响应 → 失败路径（在途标记清除 + toast）。
8. **输入边界**：unchanged 不发请求；空值不发请求；IME 组词中 Enter 不确认。
9. **虚拟列表**：滚出再滚回、重开窗口后，在途态仍在。
